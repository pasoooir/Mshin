# Pasoo City BuildIt 🏙️

**نسخه Godot بازی: 1.0.0 — هسته قابل بازی + نسخه مرورگری در حال انتشار**

[![PLAY MSHIN](https://img.shields.io/badge/▶%20PLAY-MSHIN-19b77a?style=for-the-badge)](https://pasoooir.github.io/Mshin/game/latest/)

### اجرای بازی با یک کلیک
روی دکمه **PLAY MSHIN** بالا بزن؛ لینک مستقیماً نسخه مرورگری بازی را اجرا می‌کند و برای اجرای آن نیازی به نصب Godot نیست. بازی در همان لحظه ورود، به‌صورت خودکار درخواست حالت تمام‌صفحه و قفل افقی (Landscape) می‌دهد. این قابلیت به مجوز و پشتیبانی مرورگر وابسته است؛ در مرورگرهایی که آن را مسدود می‌کنند، بازی بدون توقف در حالت قابل‌نمایش اجرا می‌شود و اولین لمس/کلیک داخل بازی نیز دوباره درخواست را امتحان می‌کند.

### اجرای نسخه Godot برای توسعه
1. Godot 4.3 یا جدیدتر (Standard) را نصب کن.
2. پوشه `godot-city-buildit` را از همین Repository با گزینه Import در Godot Project Manager باز کن.
3. فایل `godot-city-buildit/project.godot` نقطه ورود پروژه است؛ برای اجرا F5 را بزن.

GitHub Actions به‌صورت خودکار پروژه را بررسی، برای مرورگر خروجی Web تولید و در GitHub Pages منتشر می‌کند. همچنین می‌توان انتشار را از زبانه Actions با اجرای دستی workflow با نام **Mshin Playable Web** آغاز کرد.

**توجه:** نسخه Godot در پوشه مستقل نگهداری می‌شود. نسخه Web از رندرر GL Compatibility استفاده می‌کند تا با مرورگرهای موبایل سازگار باشد.

## هدف پروژه

### سند مرجع اقتصاد تولید، فروشگاه‌ها و نیازهای شهر

- **[سند فارسی اقتصاد تولید و نیازهای شهر](godot-city-buildit/docs/PRODUCTION_ECONOMY_AND_CITY_NEEDS_SPEC_FA.md)** — مرجع جامع کارخانه‌ها، فروشگاه‌ها، زنجیره‌های تولید، نیازهای ارتقای خانه، داشبورد سراسری کمبودها، UI، معماری داده، شکاف‌های فعلی و معیارهای پذیرش. [نسخه فنی انگلیسی](godot-city-buildit/docs/PRODUCTION_ECONOMY_AND_CITY_NEEDS_SPEC.md) نیز برای جزئیات مهندسی در دسترس است. مقادیر جامعه‌محور پیش از تبدیل به قانون بالانس باید دوباره اعتبارسنجی شوند.

### استاندارد مدل‌های سه‌بعدی اختصاصی شهر

- **[ماتریس مدل‌های اختصاصی و واقع‌گرایانه ساختمان‌ها](godot-city-buildit/docs/UNIQUE_REALISTIC_BUILDING_ASSET_MATRIX.md)** — فهرست انواع مسکونی، فروشگاهی، کارخانه‌ای، خدمات شهری و پارک‌های موجود در کد، مدل بصری مستقل موردنیاز هرکدام، قواعد منبع/مجوز، آزمون و معیار پذیرش. این سند فعلاً برنامه و موجودی نیازهاست؛ هیچ مدل جدیدی را انجام‌شده اعلام نمی‌کند.
- **[استاندارد ترافیک، مسیرهای لاین و ناوگان امدادی](godot-city-buildit/docs/TRAFFIC_LANE_AND_EMERGENCY_FLEET_SPEC.md)** — سرعت 4x شهر و 16x بزرگراه، حرکت راست‌دست، فاصله ایمن، مسیرهای جداگانه بزرگراه و خروج خودکار خودروهای پلیس/آتش‌نشانی.
- **[کنترل تطبیقی تقاطع‌ها](godot-city-buildit/docs/ADAPTIVE_JUNCTION_CONTROL_SPEC.md)** — چرخه سبز/زرد/تمام‌قرمز مبتنی بر صف و زمان انتظار، با حفظ توقف ایمن و رزرو انحصاری تا تکمیل مدل تعارض گردش‌ها.

### 🟡 توسعه‌های بعدی
هسته تولید و نیازهای شهر (کارخانه‌ها، ۱۴ خانواده فروشگاه، زنجیره‌های تولید، City Storage و City Needs) در کد و CI پیاده‌سازی شده است. PR #438 تعداد تعریف‌های Recipe را به ۷۳ از ۷۴ محصول رساند؛ ۷۰ محصول در حال حاضر قابل تولیدند، سه محصول با مواد/زمان مستند اما سطح بازشدن نامعلوم عمداً قفل‌اند و Tapestry به‌دلیل اختلاف ورودی Textiles همچنان غیرفعال است. ممیزی ارزش مرجع، تست صف طولانی/ذخیره/بارگذاری و آزمون Chromium موبایل اضافه شده‌اند. مقایسه و لمس روی Android فیزیکی هنوز تأیید نشده است.
لیست کامل در بخش «نقشه راه» پایین آمده است.

## فاز ۰ — پایه و حس بازی (اولویت فوری)

### ۰.۱ ظاهر و مدل‌ها
- [~] مدل‌های سه‌بعدی اختصاصی در سطح نهایی و متنوع BuildIt هنوز کامل نیستند؛ پنج GLTF محلی (چهار archetype قابل‌بازی + برج ۷۴٫۵۷۵ متریِ هنوز غیرفعال) و پنج صحنه سه‌بعدی اختصاصی فروشگاهی برای رستوران سنتی، فست‌فود، ابزارفروشی، بازار کشاورزان و فروشگاه مبلمان وجود دارد. تخصیص مدل اکنون با registry مبتنی بر شناسه دقیق نوع ساختمان انجام می‌شود: ویلا، آپارتمان، Chain Store، Small Factory و پنج صحنه فروشگاهی هرکدام فقط به نوع متناظر متصل‌اند؛ سایر فروشگاه‌ها و Tierهای کارخانه مدل عمومی دسته‌ای نمی‌گیرند و هندسه رویه‌ای اختصاصی خود را حفظ می‌کنند. برای هندسه‌های رویه‌ای، کتابخانه محلی `BuildingSurfaceLibrary.gd` اکنون نقشه‌های ۱۲۸×۱۲۸ مستقل Base Color، Normal، Roughness و Metallic را برای گچ/نما، آجر، چوب، شیشه، فلز، سفال سقف و بتن به‌صورت اشتراکی تولید می‌کند؛ قاب پنجره، شیشه و سطوح چوبی/سقف hint متریال معنایی می‌گیرند. این بافت‌ها procedural و آفلاین‌اند، نه اسکن عکاسانه؛ بنابراین بهبود کانال‌های PBR به معنی تکمیل مدل‌های اختصاصی GLTF یا تأیید بصری نهایی نیست. بیشتر انواع هنوز مدل مستقل، مقیاس/جزئیات نهایی و بازبینی موبایلی می‌خواهند.
- [x] بارگذاری مدل‌های GLB/GLTF و صحنه‌های مدل اختصاصی `.tscn` از مسیر محلی `assets/models/` با اعتبارسنجی مسیر، مقیاس اختیاری و بازگشت امن به مدل رویه‌ای در صورت نبود/نامعتبر بودن فایل.
- [x] چهار مدل GLTF محلی و آفلاین برای ویلا، آپارتمان میان‌مرتبه، فروشگاه تجاری و کارخانه، به‌علاوه یک مدل برج ۷۴٫۵۷۵ متری که هنوز به ساختمان قابل‌بازی متصل نشده است؛ مدل‌ها دارای تکسچرهای PBR داخلی Base Color، Normal و Metallic-Roughness هستند.
- [x] پنج صحنه سه‌بعدی مستقل و آفلاین برای `restaurant_traditional`، `fast_food`، `hardware_store`، `farmers_market` و `furniture_store`؛ هرکدام فرم، جزئیات تجاری و props مختص کاربری خود را دارند و از کتابخانه PBR محلی استفاده می‌کنند. تست GameplaySmoke بارگذاری، ایجاد MeshInstance3D و اتصال دقیق هر scene به building type را بررسی می‌کند. مدل فروشگاه و کارخانه در این مرحله نمای عمومی دسته هستند، نه مدل اختصاصی هر برند/کاربری؛ ویژوال اختصاصی Building Supplies، Art Supplies و ویلای مرحله اول حفظ شده است.
- [x] اعتبارسنجی CI فقط مسیرهای واقعاً استفاده‌شده در فراخوانی‌های بارگذاری منبع Godot را بررسی می‌کند؛ رشته‌های آزمایشی `res://` به‌اشتباه وابستگی فایل تلقی نمی‌شوند و این رفتار تست رگرسیون دارد.
- [x] جزئیات رویه‌ای ساختمان‌ها: پنجره قاب‌دار، ورودی، سایه‌بان، دودکش، تابلو و جزئیات سقف
- [x] زمین چندطیفی، علف‌های سه‌بعدی MultiMesh، آسفالت procedural، جدول و پیاده‌رو
