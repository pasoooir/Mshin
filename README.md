# Pasoo City BuildIt 🏙️

**نسخه Godot بازی: 1.0.0 — هسته قابل بازی + نسخه مرورگری در حال انتشار**

[![PLAY MSHIN](https://img.shields.io/badge/▶%20PLAY-MSHIN-19b77a?style=for-the-badge)](https://pasoooir.github.io/Mshin/game/latest/)

### اجرای بازی با یک کلیک
روی دکمه **PLAY MSHIN** بالا بزن؛ لینک مستقیماً نسخه مرورگری بازی را اجرا می‌کند و برای اجرای آن نیازی به نصب Godot نیست. بازی در همان لحظه ورود، به‌صورت خودکار درخواست حالت تمام‌صفحه و قفل افقی (Landscape) می‌دهد. این قابلیت به مجوز و پشتیبانی مرورگر وابسته است؛ در مرورگرهایی که آن را مسدود می‌کنند، بازی بدون توقف در حالت قابل‌نمایش اجرا می‌شود و اولین لمس/کلیک داخل بازی نیز دوباره درخواست را امتحان می‌کند.

### اجرای نسخه Godot برای توسعه
1. Godot 4.3 یا جدیدتر (Standard) را نصب کن.
2. پوشه `godot-city-buildit` را از همین Repository با گزینه Import در Godot Project Manager باز کن.
3. فایل `godot-city-buildit/project.godot` نقطه ورود پروژه است؛ برای اجرا F5 را بزن.

GitHub Actions به‌صورت خودکار پروژه را بررسی، برای مرورگر خروجی Web تولید و در GitHub Pages منتشر می‌کند. همچنین می‌توان انتشار را از زبانه Actions با اجرای دستی workflow با نام **Mshin Playable Web** آغاز کرد.

**توجه:** نسخه Godot در پوشه مستقل نگهداری می‌شود. نسخه Web از رندرر GL Compatibility استفاده می‌کند تا با مرورگرهای موبایل سازگار باشد.

#### مرجع رفتاری SimCity BuildIt

دو دکمه مثبت کنار موجودی ارزها در گوشه بالای HUD دو مسیر اقتصادی متفاوت دارند و نباید به یک پنجره عمومی یا پیام وضعیت مشترک متصل باشند:

1. **Simoleons (+) — تبدیل SimCash به Simoleons**
   - راهنمای رسمی EA می‌گوید Simoleons ارز روزمره برای خرید ساختمان‌ها و ارتقای جاده‌هاست؛ بازیکن آن را در جریان بازی کسب می‌کند یا از Web Store می‌خرد.
   - SimCash ارز پریمیوم است و می‌تواند مستقیماً به Simoleons تبدیل شود.
   - الگوی تعامل مشاهده‌شده در مرجع جامعه بازی: لمس + کنار Simoleons پنجره تبدیل را باز می‌کند؛ بازیکن مقدار/بسته تبدیل را انتخاب می‌کند و سپس عمل تبدیل را تأیید می‌کند. این پنجره باید موجودی فعلی هر دو ارز، مقدار SimCash مصرفی، مقدار Simoleons دریافتی و نتیجه پس از تبدیل را روشن نمایش دهد.
   - نسبت‌ها و گزینه‌های عددی تبدیل باید داده‌محور و قابل تنظیم باشند. تا زمانی که از نسخه زنده بازی یا منبع معتبر عدد دقیق تأیید نشده، هیچ نرخ یا بسته‌ای نباید «نرخ رسمی EA» معرفی شود.
   - تبدیل فقط با تأیید صریح بازیکن انجام شود؛ لغو یا بستن پنجره نباید موجودی را تغییر دهد. کمبود SimCash، مقدار نامعتبر و دوبار فشردن تأیید باید ایمن مدیریت شوند.

2. **SimCash (+) — فروشگاه ارز پریمیوم**
   - راهنمای رسمی EA، SimCash را ارز پریمیوم معرفی می‌کند که برای تسریع تولید، افزایش خانه‌های صف فروشگاه، بازکردن ظرفیت انبار/گسترش و تبدیل به Simoleons استفاده می‌شود.
   - لمس + کنار SimCash در بازی مرجع فروشگاه SimCash را باز می‌کند؛ بنابراین این دکمه نباید پنجره تبدیل به Simoleons را باز کند.
   - کاتالوگ فروشگاه رسمی EA شامل بسته‌های چنداندازه SimCash و نیز بسته‌های Simoleons، پیشنهادهای ویژه و پاداش‌های روزانه است. Web Store رسمی همچنین ممکن است برای خریدهای واجد شرایط پاداش/Bonus جداگانه داشته باشد؛ این مزایا را نباید بدون پیاده‌سازی و پیکربندی واقعی به فروشگاه Mshin نسبت داد.
   - فروشگاه Mshin باید بسته‌ها را از کاتالوگ داده‌محور بخواند و برای هر مورد مقدار ارز، قیمت نمایشی، شناسه محصول، برچسب bonus/offer و وضعیت دسترس‌پذیری را نشان دهد. قیمت‌ها و بسته‌های EA فقط مرجع مطالعه‌اند؛ قیمت‌گذاری Mshin باید مستقل و قابل تغییر باشد.

#### شبیه‌سازی پرداخت در Mshin تا زمان اتصال درگاه واقعی

- در فاز فعلی، جریان خرید باید **Sandbox/Mock Purchase** باشد: انتخاب بسته ← نمایش خلاصه سفارش ← تأیید شبیه‌سازی پرداخت ← ثبت نتیجه موفق/ناموفق/لغوشده ← اعطای ارز فقط در نتیجه موفق.
- رابط پرداخت، کاتالوگ محصول، شناسه سفارش، وضعیت تراکنش، تاریخچه خرید و لایه اعطای ارز باید از ارائه‌دهنده پرداخت مستقل باشند تا بعداً بتوان درگاه واقعی را بدون بازنویسی UI و اقتصاد جایگزین کرد.
- تراکنش آزمایشی باید به‌وضوح با برچسب «پرداخت آزمایشی؛ هیچ وجه واقعی دریافت نمی‌شود» نمایش داده شود. در این مرحله نباید کارت بانکی، اطلاعات حساس پرداخت یا ادعای پرداخت واقعی دریافت/ذخیره شود.
- اعطای ارز باید idempotent باشد: یک شناسه سفارش فقط یک بار بتواند ارز اعطا کند؛ دوبار کلیک، بارگذاری مجدد یا retry نباید موجودی را دوباره افزایش دهد.
- هر خرید آزمایشی باید در دفتر تراکنش ثبت شود (شناسه یکتا، محصول، ارز/مقدار، قیمت نمایشی و واحد، وضعیت، زمان، منبع mock). اعتبارسنجی سمت سرور و رسید امضاشده درگاه واقعی در فاز اتصال درگاه الزامی خواهد بود؛ کلاینت به‌تنهایی مرجع قابل اعتماد پرداخت واقعی نیست.
- خرید SimCash و تبدیل SimCash به Simoleons دو عملیات مجزا هستند: خرید، ارز پریمیوم را از مسیر سفارش پرداخت تأمین می‌کند؛ تبدیل، فقط موجودی داخلی SimCash را طبق نرخ پیکربندی‌شده کم و Simoleons را زیاد می‌کند.
- Golden Keys نباید در این دو مسیر قابل خرید یا تبدیل شوند؛ راهنمای EA تصریح می‌کند این ارز از مسیرهای بازی کسب می‌شود و با Simoleons یا SimCash خریداری نمی‌شود.

## فاز ۰ — پایه و حس بازی (اولویت فوری)

### ۰.۱ ظاهر و مدل‌ها
- [~] مدل‌های سه‌بعدی اختصاصی در سطح نهایی و متنوع BuildIt هنوز کامل نیستند؛ پنج GLTF محلی (چهار archetype قابل‌بازی + برج ۷۴٫۵۷۵ متریِ هنوز غیرفعال) و پنج صحنه سه‌بعدی اختصاصی فروشگاهی برای رستوران سنتی، فست‌فود، ابزارفروشی، بازار کشاورزان و فروشگاه مبلمان وجود دارد. تخصیص مدل اکنون با registry مبتنی بر شناسه دقیق نوع ساختمان انجام می‌شود: ویلا، آپارتمان، Chain Store، Small Factory و پنج صحنه فروشگاهی هرکدام فقط به نوع متناظر متصل‌اند؛ سایر فروشگاه‌ها و Tierهای کارخانه مدل عمومی دسته‌ای نمی‌گیرند و هندسه رویه‌ای اختصاصی خود را حفظ می‌کنند. برای هندسه‌های رویه‌ای، کتابخانه محلی `BuildingSurfaceLibrary.gd` اکنون نقشه‌های ۱۲۸×۱۲۸ مستقل Base Color، Normal، Roughness و Metallic را برای گچ/نما، آجر، چوب، شیشه، فلز، سفال سقف و بتن به‌صورت اشتراکی تولید می‌کند؛ قاب پنجره، شیشه و سطوح چوبی/سقف hint متریال معنایی می‌گیرند. این بافت‌ها procedural و آفلاین‌اند، نه اسکن عکاسانه؛ بنابراین بهبود کانال‌های PBR به معنی تکمیل مدل‌های اختصاصی GLTF یا تأیید بصری نهایی نیست. بیشتر انواع هنوز مدل مستقل، مقیاس/جزئیات نهایی و بازبینی موبایلی می‌خواهند.
- [x] بارگذاری مدل‌های GLB/GLTF و صحنه‌های مدل اختصاصی `.tscn` از مسیر محلی `assets/models/` با اعتبارسنجی مسیر، مقیاس اختیاری و بازگشت امن به مدل رویه‌ای در صورت نبود/نامعتبر بودن فایل.
- [x] چهار مدل GLTF محلی و آفلاین برای ویلا، آپارتمان میان‌مرتبه، فروشگاه تجاری و کارخانه، به‌علاوه یک مدل برج ۷۴٫۵۷۵ متری که هنوز به ساختمان قابل‌بازی متصل نشده است؛ مدل‌ها دارای تکسچرهای PBR داخلی Base Color، Normal و Metallic-Roughness هستند.
- [x] پنج صحنه سه‌بعدی مستقل و آفلاین برای `restaurant_traditional`، `fast_food`، `hardware_store`، `farmers_market` و `furniture_store`؛ هرکدام فرم، جزئیات تجاری و props مختص کاربری خود را دارند و از کتابخانه PBR محلی استفاده می‌کنند. تست GameplaySmoke بارگذاری، ایجاد MeshInstance3D و اتصال دقیق هر scene به building type را بررسی می‌کند. مدل فروشگاه و کارخانه در این مرحله نمای عمومی دسته هستند، نه مدل اختصاصی هر برند/کاربری؛ ویژوال اختصاصی Building Supplies، Art Supplies و ویلای مرحله اول حفظ شده است.
